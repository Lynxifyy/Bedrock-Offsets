  predicate, not "not abstract".

  method lists each restart the index at an absolute value, then delta.

  keep rules; `ProguardRuleTests` guards drift.
- Verified end-to-end: fixed APK reports `Gson models: 31 models instantiable`,

## Bedrock-Offsets: "malformed section map payload" on a real APK (fixed, PR #4)
- **Symptom**: on a real 342 MB `libminecraftpe.so`, after a successful mmap:
  `[RUST] Entry point 0x0, 0 sections` then
  `[RUST] the engine returned a malformed section map payload`.
- **Root cause**: `SectionInfo.delta = sh_addr.wrapping_sub(sh_offset)`. A
  **non-loaded** section (`.shstrtab`, `.comment`, debug) has addr 0 and an
  offset inside the file, so the u64 wraps above `i64::MAX`
  (`18446744073688580096`). serde_json writes it; Kotlin reads `delta` as a
  `Long`; Gson throws -> `decode` maps it to `Unknown` ("report this message").
  **Every real ELF has a `.shstrtab`, so this fails on the first real library
  and never on fixtures that omit non-allocated sections.** Fix: `serialize_delta`
  -> `i64`.
- **`Elf::lazy_parse` leaves `program_headers` AND `section_headers` EMPTY.**
  Anything counting them reports 0 (the "0 sections" log) and `soname` is always
  None. Use `parse_section_headers` / a new `parse_program_headers`, and read
  `DT_SONAME` from `.dynamic` (`sh_link` -> its strtab). Also fixed the
  build-id `PT_NOTE` fallback in `symbols.rs`, which iterated the empty table.
- **Scanner dedup bug**: `per_chunk.sort_unstable(); per_chunk.dedup()` on
  `Vec<Vec<(usize,usize)>>` only removes identical *chunks*, not duplicated
  positions. Flatten first. Trigger: a match inside the 32-byte chunk overlap
  plus any other match in the same chunk.
- **RTTI on RELA builds**: the `if raw == 0 { continue }` ran *before* the
  relocation lookup, so vtables were skipped when in-place slots are 0 (the
  normal RELA shape). Same for the `type_info` name pointer. Consult the
  relocation table first.
- **Memory cap (hard constraint)**: the shipped `adrp_add_page_off` pattern is
  `?? ?? ?? ?? ?? ?? ?? 91` — **1 fixed byte of 8**, so ~1/256 of a 342 MB
  `.text` matches (~1.3M hits, ~150 MB of `PatternHit`). Added
  `MAX_HITS_PER_PATTERN = 4096` / `MAX_HITS_TOTAL = 32768` + a `truncated` flag
  surfaced in the Kotlin log.
- **Kotlin**: `TRIM_MEMORY_UI_HIDDEN` (20) fires on backgrounding (file picker)
  and `level >= TRIM_MEMORY_RUNNING_LOW` matched it -> spurious "low on memory".
  Extractor wrote to `cacheDir/engine`, outside `ScanCache` -> "Clear cache"
  never freed the 342 MB `.so`; now uses `scanCache.libraryDir`. `clearCache`
  ran shred+fsync on the main thread (ANR) -> moved to `ioDispatcher` and
  refused during a scan. The export assigned `extractionJob`, so `cancel()`
  cancelled the export.
- **Two review claims that were WRONG** (verified against vendored sources):
  Capstone regs 2/3/5 ARE `ARM64_REG_FP/LR/SP` (not bogus); unsigned
  `is_multiple_of` stabilised in 1.87 so `rust-version = "1.88"` is fine.
  Still hardened: reg constants now come from `Arm64Reg` with
  `const _: () = assert!(..)` pins.
- Tests: Kotlin 174, Rust 137, Python 82, all green; clippy/fmt/ktlint/lint clean.

## Bedrock-Offsets release v1.0.2
- Merged PR #4 (section-map/parser fixes) then PR #5 (version bump) with the
  async squash merge API; bumped `versionCode` 2 -> 3, `versionName` "1.0.1" ->
  "1.0.2". Tagged `v1.0.2` on `main` (b3d5d57); `release.yml` published the APK.
- Published asset verified independently: `verify_release.py` all-ok,
  `Gson models: 31 models instantiable`, versionCode 3 / versionName 1.0.2.
  sha256 `ebd74f69cae2ba098eaba76b6ae412fda4ec5f854acf1335bf0c53ab14609673`.
- **Gotcha**: the v1.0.2 APK is *byte-identical in size* (5239010) to v1.0.1 even
  though the engine changed (+1648 bytes, different sha256). AGP's 16 KB page
  alignment absorbs small `.so` growth into the same padding, so **size equality
  does not mean an unchanged build** — compare the embedded `.so` hash or the
  APK sha256 instead. `unzip` is NOT installed in this container; use Python
  `zipfile` to inspect APKs.
- **Gotcha**: the debug signing certificate differs between CI runs
  (v1.0.1 `e2ae28…`, v1.0.2 `11d265…`) because the ephemeral runner generates a
  fresh debug keystore. Android refuses to install an update signed with a
  different key, so a user must uninstall the previous build first. Real signing
  needs the four `SIGNING_*` secrets.
