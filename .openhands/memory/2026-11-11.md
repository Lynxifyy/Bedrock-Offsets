
## Bedrock-Offsets: Gson + R8 release shrink fix
- Reported symptom: release-only `JsonIOException: Abstract classes can't be
  instantiated! Class name: ...data.native.e`. The user's doc claimed
  `app/proguard-rules.pro` was missing — it exists and is tracked; the bug was
  inside it (kept `...model.**` / `...data.model.**`, both nonexistent).
- Real models: `data/native` (engine payloads, incl. `EnginePayloads.kt`,
  `ScanOutcome.kt`, `SymbolReport.kt`, `SectionMap.kt`, `VtableMap.kt`),
  `data/export` (OffsetExporter), `data/cache` (ResultCache.Envelope),
  `data/patterns` (SignaturePack), `ui/state` (ScanResultSummary etc).
- Evidence chain: `dexdump` on the shipped APK showed `data/native/e` =
  `ExtractionPayload` as `PUBLIC ABSTRACT` with no `<init>`; R8 `mapping.txt`
  confirmed the identity. `ElfMetadataPayload`/`ScanOutcomePayload` lost their
  ctor without being marked abstract, so "present + has <init>" is the precise
  predicate, not "not abstract".
- New `scripts/dex.py`: pure-Python DEX reader (header, string/type/method/class
  tables, class_data direct+virtual lists). Pitfall hit: direct and virtual
  method lists each restart the index at an absolute value, then delta.
- `verify_release.py check_gson_models` uses it; `GSON_MODEL_CLASSES` mirrors the
  keep rules; `ProguardRuleTests` guards drift.
- Verified end-to-end: fixed APK reports `Gson models: 31 models instantiable`,
  fields `path`/`sha256`/`size` and `<init>` present in the release dex.
- PR #2 (fix/gson-r8-release-shrink), commit ed9c62c; all 3 Android CI jobs green.

## Bedrock-Offsets release v1.0.1
- Merged PR #2 (Gson/R8 keep fix) and PR #3 (version bump) with the async squash
  merge API; both CI runs green (all three jobs).
- Version lives in `app/build.gradle.kts` (`versionCode`/`versionName`). Bumped
  1 -> 2 / "1.0.0" -> "1.0.1". `scripts/verify_version.py --tag vX.Y.Z` enforces
  the tag matches `versionName`, so the tag push fails fast on a mismatch.
- Release flow: push tag `v*` -> `release.yml` cross-compiles the engine, runs
  verify_release.py, renames the APK to `bedrock-offset-extractor-<tag>.apk`,
  generates notes with changelog.py, `gh release create`. Do NOT create the
  release by hand — the workflow does it.
- **No signing secrets on this repo**, so the APK is debug-signed. `release.yml`
  warns and skips the "must be signed" guard when `SIGNING_KEYSTORE_BASE64` is
  absent; add that + the 3 password/alias secrets to sign properly.
- v1.0.1 verified after publication: downloaded the asset, ran
  `verify_release.py` -> `Gson models: 31 models instantiable`, apksigner shows
  the Android debug cert, aapt2 shows versionCode 2 / versionName 1.0.1.
  sha256 650c2dbd3a7659f3548785890d97f720d0317d8ce768a06812816abb2df95099.
- `feat/offset-extractor-engine` is fully contained in `main` (squashed as PR
  #1) despite showing as unmerged; the branch can be deleted safely.
