# 2026-11-12 — Bedrock-Offsets: the two flagged items

Context: user said *"Fix the flags then, and after… Get the Minecraft apks from
mcpedl.org"*. "The two flags" = (1) branch targeting, (2) the `patterns.json`
signature pack. Both fixed on a clean branch and shipped as PR #9.

## Real library obtained
- mcpedl.org download is a **POST to `/show_file.php`** with a `file_id`; the
  version page is e.g. `https://mcpedl.org/minecraft-pe-26-62-apk/`. Resolved to
  `https://file.mcpedl.org/uploads_files/06-11-2026/minecraft-26-62.apk`.
- APK 378,825,233 bytes. `lib/arm64-v8a/libminecraftpe.so` = **342,231,392
  bytes**, `.text` = **215,608,648 bytes**.
- The library is **NOT stripped**: 90,670 defined dynsyms, **95 `Java_*` JNI
  entry points**, 4,619 length-prefixed RTTI names in `.rodata`. But the
  **internal Minecraft classes are stripped** — there is no
  `ClientInstance`/`LocalPlayer`/`GameMode` symbol; the `_Z*` names that exist
  are vendored libs (v8, cohtml, xbox, webrtc, leveldb). So the only
  Bedrock-specific, *verifiable* anchors are the JNI entry points.

## Flag 2 — the pack (the real defect)
The pack held 10 **instruction-shape** patterns (`frame_push_x29_x30`,
`pacibsp_prologue`). Each matched thousands of places and was named after
nothing, so `verify_against_symbols` found no symbol with that name → every hit
`UNVERIFIED` → **confidence permanently 0**. Measured: 12,374 raw matches,
8,191 discarded as non-prologues, 0 verified.

Fix, in two parts:
1. **New `scripts/derive_patterns.py`** — parses `.dynsym`, keeps defined
   `Java_*` symbols, and grows each signature from the symbol's bytes until it
   is unique in `.text` (8..64 bytes, step 4). 91 unique signatures.
   - **Gotcha that cost a debug cycle**: the in-`.text` index is
     `st_value - text.sh_addr`, NOT `st_value - delta` (`delta = sh_addr -
     sh_offset` is the *file-offset → VA* direction). Using `delta` put every
     signature `0x6834c80` bytes (= `.text`'s address) into the section.
   - `bytes.count` **skips overlaps**; uniqueness needs a `find` loop or a run
     of identical bytes looks unique at the first length.
2. **Pipeline order fix** (`jni_bridge.rs` + `scanner/verifier.rs`) — the
   prologue check ran **before** the symbol cross-check, so it discarded
   correct offsets whose shape is not a stack frame. A **leaf** is exactly that
   (`isEduMode` = `mov w0, wzr; ret`): 27 of 91 confirmed offsets were lost.
   Now the cross-check runs first, and `verify_prologues` keeps a hit whose
   `verification_status == Verified` even when `verdict.accepted` is false
   (and leaves `prologue_kind = None` so the row's detail is not a lie).

Result on the real library: **91/91 matched, 0 discarded, 91 verified,
0 conflicts, 100% confidence.**
