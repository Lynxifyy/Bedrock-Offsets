## INTERNALCPP_OFFSETS follow-ups (F1-F10)

- Root cause candidate for the 1432 zero-slot classes: `collect_vtables` treated
  *every* slot pointing at a `type_info` as a vtable's `vtable[-1]`, including the
  base pointers inside `__si_class_type_info` / `__vmi_class_type_info`. That
  produced bogus vtables whose header (`bogus+0`, `bogus+8`) could coincide with a
  real vtable's first slot, so `collect_class_slots` broke out immediately and
  reported `slotCount: 0`. Fixed with `is_plausible_vtable` (small multiple-of-8
  offset-to-top + a first slot that is relocated or executable). Regression test
  `rtti_test::a_type_info_pointer_in_a_base_array_is_not_a_vtable` fails without
  the filter (2 vtables) and passes with it (1).
- `internal::read_at` and `internal::is_executable` are now `pub(crate)` so rtti
  can reuse them.
- Diagnostic: `rtti::tests::dump_vtable_context` is `#[ignore]`d and reads

  relocation targets.

## Signature pass stall + memory, and bogus vtable groups (v1.0.9 / v1.0.10)

- **The hours-long "round 1" on a real library was Aho-Corasick, not the emit loop.**
  `PatternSet::new` used to feed *every* literal run to the automaton; a two-byte run
  between wildcards (`... FF ?? ?? ...`) matches millions of positions, so every scan was
  hours. Now each pattern is anchored on its **longest** literal run. Cost stays linear in
  `.text`; the extra candidates a shorter anchor used to filter are handled by the
  existing full-pattern verification.
- Automaton cost is ~1 KB per pattern → ~1 GB at a million candidates. `count_at_function_starts`
  now builds one `PatternSet` per group of **8192** candidates and rescans `.text` per group
  (seconds per group, flat peak). `is_cancelled` is checked per wave.
- `SlotRecord`s are shared as `Vec<Arc<SlotRecord>>` between `ClassRecord::slots` and the
  primary `VtableGroup`, and `signature` is `Arc<str>` (serde `rc` feature). Mutating in the
  merge/override loops uses `Arc::make_mut`, which is free only because `ClassRecord::slots`
  is filled **after** those loops (leave `slots: Vec::new()` in the constructor!).
- **Bogus vtable groups**: a zeroed word that carries a `R_AARCH64_RELATIVE` relocation plus a
  relocated `type_info` pointer was accepted as a vtable header. It gave `Actor`/`Mob`/`Level`
  a one-slot group at a nonsense offset-to-top, and sorting groups by address alone made that
  group the reported primary (`slotCount: 1`). Fixes: offset-to-top is read **in place** (it is
  plain data even in a RELA build; never a relocation target), a zeroed offset-to-top that has
  a nonzero relocation is rejected, and groups are ordered offset-0-first.
  Regression tests: `rtti_test::a_relocated_offset_to_top_is_not_a_vtable`.
- 607 classes disappear from the class list after that fix. They are RTTI-only interfaces
  (`ActorEventListener`, `Audio::IAudioAssetProvider`, …): their `type_info` exists because
  other classes inherit from them, but no vtable is emitted. Verified one (ActorEventListener)
  byte by byte with pyelftools — no vtable at the reported address, only a relocated pointer.
- Host numbers on `libminecraftpe.so` from `minecraft-26-60.apk` (release, x86_64, ~100 s):
  6386 classes, 0 zero-slot, 865 399 slots (617 456 with size), 626 040 slot signatures
  (575 355 unique), 512 803 function signatures (469 487 unique), 11 354 data symbols,
  peak RSS 1517 MB. `BEDROCK_LIB=... BEDROCK_OUT=... cargo test --release --test
  real_library_stats -- --ignored --nocapture` is the harness (`tests/real_library_stats.rs`).
